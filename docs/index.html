Two paths, one outcome

根据作品，选择展示方式。

01 / 已有网页

让现有页面直接上线。

静态网页直接部署；需要构建的项目先生成包含 HTML 的静态产物，检查资源路径与主要交互，再发布到 GitHub Pages。

现有网页 → 静态产物 → 公开页面
02 / 没有网页

为作品做一个介绍页。

脚本、工具或其他非网页作品，根据真实功能补充产品介绍、使用示例和快速开始，提供源码入口，让访客了解作品内容。

产品内容 → HTML 落地页 → 公开页面
The workflow

从源码，到可访问的链接。

01

确认发布目标

识别作品内容、GitHub 账号与仓库，检查准备公开的文件。

02

完整上传源码

保留源码、资源与运行说明，排除凭据和私人数据。

03

准备 HTML

部署现有网页，或根据作品内容制作介绍页。

04

部署与验证

验证首页、资源和主要链接，交付仓库与展示页地址。
